### 目录各干什么

| 位置 | 作用 |
|---|---|
| `pom.xml` | 采购清单：要哪些库、什么版本、Java 几 |
| `mvnw` + `.mvn/` | 自带的 Maven，梯子 |
| `src/main/java/` | 写代码的地方，所有类都在这里 |
| `src/main/resources/application.properties` | 项目配置，一行一项（端口、数据库地址……） |
| `src/main/resources/static/` | 图片、CSS 这类静态文件 |
| `src/test/java/` | 测试代码，`./mvnw test` 跑它 |
| `target/` | 编译产物，可整个删掉，别手改 |

真正要关心的只有三个：`pom.xml`、`src/main/java`、`application.properties`。

### 第一个接口

`HelloController.java` 里：

- 类上 `@RestController`：这个类是前台，负责接网址；方法 return 的字符串直接写回浏览器。
- 方法上 `@GetMapping("/hello")`：用 GET 访问 `/hello` 就跑这个方法。

访问 `http://localhost:8080/hello` → `Hello, World!`，状态码 200。

### 踩过的坑

- 注解标红 = 缺 import。VSCode 里光标停在红字上按 `⌘ .` 补上。
- 还没写接口时，访问根路径返回 404 是正常的：服务起来了，只是没有这个路径。

## 疑问记录

### Spring Boot 这些文件夹都干什么用？

见上面「目录各干什么」。核心是三个：`pom.xml` 说清楚要什么库，`src/main/java` 放代码，`application.properties` 放配置。`target/` 是编译产物，删了会重新生成。

### `@RestController` 和 `@GetMapping` 是干什么的？

注解是贴在类或方法上的标签，Spring 启动时扫一遍才知道怎么处理。

- `@RestController`：贴类上，说明这个类负责接网址，返回的内容直接写进响应体，不当网页去找。
- `@GetMapping("/hello")`：贴方法上，说明 GET 访问 `/hello` 时执行这个方法。

合起来读：这个类当前台 → 收到 `/hello` 的 GET → 交给这个方法 → 它返回的字符串原样写回浏览器。

### 为什么 java 文件夹要分这么多层包？

`com/example/jwt_lab` 不是三个包，是一个包名被斜杠展开。类全名是 `com.example.jwt_lab.HelloController`。

- 包名 = 反写域名 + 项目名，保证全世界两个 `HelloController` 不撞车。
- 包必须和文件夹一一对应，对不上编译不过——这是 Java 的规矩，不是 Spring 的。
- 包名不能有横杠，所以 Artifact 填 `jwt-lab`，Initializr 给了 `jwt_lab`。

### 这个包能干啥？

包本身不干活，它只是架子。作用三个：给类一个位置、防重名、划范围（Spring 只扫启动类所在包以下）。

能力在类和方法里。另外同一个包里不写 `public` 的类和方法只有同包能看见，叫「包内可见」；目前都写的 `public`，用不上。

### UUID 是干嘛的？

全名 Universally Unique Identifier，通用唯一识别码。一串 128 位的随机数，打印成 36 个字符：8-4-4-4-12，用横杠隔开。

作用：当**编号**用。我们拿它当通行证编号（token）——随机、几乎不会重复、看不出规律。对比 `1、2、3` 这种自增编号，别人能顺着猜下一个。

`UUID.randomUUID()` 生成，`.toString()` 转成字符串才能塞进 String 返回。它只是随机，不是加密；真正的 JWT 靠签名。

### `@RequestParam String username` 是干啥的？

拆成两半看：

- `String username`：这里要一个字符串变量。
- `@RequestParam`：这个值从哪来——去网址 `?` 后面按参数名 `username` 找。

网址 `/login?username=admin&password=admin123`，`?` 后面是两对 `名=值`，用 `&` 隔开。Spring 按名字对上，把 `"admin"` 塞进 `username`，把 `"admin123"` 塞进 `password`。

两个参数各写一个 `@RequestParam`，因为每个都得说清楚从哪取。默认必填，网址少一个就是 400；写 `@RequestParam(required = false)` 就变成可选。

### `equals` 是干啥的？

比较两个字符串的**内容**是否相同，返回 true / false。

坑在 `==`：它比的是“是不是同一个对象”，不是内容。

```java
String a = "admin";
String b = new String("admin");
a == b        // false，两个不同的对象
a.equals(b)   // true，内容一样
```

还有个小习惯：把常量写前面，`"admin".equals(username)`。这样 `username` 是 null 时只返回 false；写反了 `username.equals("admin")`，null 会直接空指针崩掉。

### 过滤器（Filter）是干嘛的，重要在哪？

- 拦在所有请求前面，Controller 之前执行。写一次，对所有接口生效。
- 不这么做的后果：每个接口方法里都抄一遍校验，10 个接口写 10 次，改规则要改 10 处。
- 真实用途：登录校验、记日志、限流、跨域。Spring Security 本质就是一串 Filter。
- 术语别混：Filter 过滤器；Listener 监听器是另一回事（监听应用启动/关闭）。

### 为什么 `doFilter` 非要抛 `IOException` 和 `ServletException`？

- 接口签名规定的，调用方是 Tomcat。
- `IOException`：读写网络可能失败（客户端断开、写响应失败）。
- `ServletException`：Servlet 处理过程中的通用错误。
- 不用主动 new 出来；能处理就 try/catch，不能就往上抛给 Tomcat。

### `doFilter` 的三个参数是干啥的？

- `request`、`response`、`chain` 都是 Tomcat 传进来的，不是自己造。
- request 拿请求，response 写响应，chain 是「下一关的钥匙」。
- `chain.doFilter(...)` 把请求交给链上的下一个（下一个 Filter 或最终 Controller）。这叫责任链：每人干一段再往下传。

### `HttpServletRequest`、`getMethod()`、`getRequestURI()` 有啥用？

- `HttpServletRequest`：请求对象，能拿请求方法、路径、请求头、参数、body。
- `getMethod()`：GET 还是 POST。
- `getRequestURI()`：路径，如 `/hello`，不含 `?` 后面的参数。
- 要强转是因为 Filter 接口给的是通用款 `ServletRequest`，HTTP 专用方法只在 `HttpServletRequest` 上。

### `@Component`、`@Override`、`implements` 是啥？

- `implements Filter`：声明实现 Filter 接口，必须交出 `doFilter` 方法。接口就是一份合同。
- `@Component`：告诉 Spring 启动时创建这个类并注册成过滤器。
- `@Override`：给编译器看的，声明「这是重写接口的方法」，名字写错立刻报错。可省略，不建议省。
