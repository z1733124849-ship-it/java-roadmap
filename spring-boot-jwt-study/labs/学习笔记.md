### 目录各干什么

| 位置 | 作用 |
|---|---|
| `pom.xml` | 采购清单：要哪些库、什么版本、Java 几 |

## 疑问记录

### Spring Boot 这些文件夹都干什么用？

见上面「目录各干什么」。核心是三个：`pom.xml` 说清楚要什么库，`src/main/java` 放代码，`application.properties` 放配置。`target/` 是编译产物，删了会重新生成。

### `@RestController` 和 `@GetMapping` 是干什么的？

注解是贴在类或方法上的标签，Spring 启动时扫一遍才知道怎么处理。

- `@RestController`：贴类上，说明这个类负责接网址，返回的内容直接写进响应体，不当网页去找。
- `@GetMapping("/hello")`：贴方法上，说明 GET 访问 `/hello` 时执行这个方法。

合起来读：这个类当前台 → 收到 `/hello` 的 GET → 交给这个方法 → 它返回的字符串原样写回浏览器。

### 为什么 java 文件夹要分这么多层包？

`com/example/jwt_lab` 不是三个包，是一个包名被斜杠展开。类全名是 `com.example.jwt_lab.HelloController`。

- 包名 = 反写域名 + 项目名，保证全世界两个 `HelloController` 不撞车。
- 包必须和文件夹一一对应，对不上编译不过——这是 Java 的规矩，不是 Spring 的。
- 包名不能有横杠，所以 Artifact 填 `jwt-lab`，Initializr 给了 `jwt_lab`。

### 这个包能干啥？

包本身不干活，它只是架子。作用三个：给类一个位置、防重名、划范围（Spring 只扫启动类所在包以下）。

能力在类和方法里。另外同一个包里不写 `public` 的类和方法只有同包能看见，叫「包内可见」；目前都写的 `public`，用不上。

### UUID 是干嘛的？

全名 Universally Unique Identifier，通用唯一识别码。一串 128 位的随机数，打印成 36 个字符：8-4-4-4-12，用横杠隔开。

作用：当**编号**用。我们拿它当通行证编号（token）——随机、几乎不会重复、看不出规律。对比 `1、2、3` 这种自增编号，别人能顺着猜下一个。

`UUID.randomUUID()` 生成，`.toString()` 转成字符串才能塞进 String 返回。它只是随机，不是加密；真正的 JWT 靠签名。

### `@RequestParam String username` 是干啥的？

拆成两半看：

- `String username`：这里要一个字符串变量。
- `@RequestParam`：这个值从哪来——去网址 `?` 后面按参数名 `username` 找。

网址 `/login?username=admin&password=admin123`，`?` 后面是两对 `名=值`，用 `&` 隔开。Spring 按名字对上，把 `"admin"` 塞进 `username`，把 `"admin123"` 塞进 `password`。

两个参数各写一个 `@RequestParam`，因为每个都得说清楚从哪取。默认必填，网址少一个就是 400；写 `@RequestParam(required = false)` 就变成可选。

### `equals` 是干啥的？

比较两个字符串的**内容**是否相同，返回 true / false。

坑在 `==`：它比的是“是不是同一个对象”，不是内容。

```java
String a = "admin";
String b = new String("admin");
a == b        // false，两个不同的对象
a.equals(b)   // true，内容一样
```

还有个小习惯：把常量写前面，`"admin".equals(username)`。这样 `username` 是 null 时只返回 false；写反了 `username.equals("admin")`，null 会直接空指针崩掉。

### 过滤器（Filter）是干嘛的，重要在哪？

- 拦在所有请求前面，Controller 之前执行。写一次，对所有接口生效。
- 不这么做的后果：每个接口方法里都抄一遍校验，10 个接口写 10 次，改规则要改 10 处。
- 真实用途：登录校验、记日志、限流、跨域。Spring Security 本质就是一串 Filter。
- 术语别混：Filter 过滤器；Listener 监听器是另一回事（监听应用启动/关闭）。

### 为什么 `doFilter` 非要抛 `IOException` 和 `ServletException`？

- 接口签名规定的，调用方是 Tomcat。
- `IOException`：读写网络可能失败（客户端断开、写响应失败）。
- `ServletException`：Servlet 处理过程中的通用错误。
- 不用主动 new 出来；能处理就 try/catch，不能就往上抛给 Tomcat。

### `doFilter` 的三个参数是干啥的？

- `request`、`response`、`chain` 都是 Tomcat 传进来的，不是自己造。
- request 拿请求，response 写响应，chain 是「下一关的钥匙」。
- `chain.doFilter(...)` 把请求交给链上的下一个（下一个 Filter 或最终 Controller）。这叫责任链：每人干一段再往下传。

### `HttpServletRequest`、`getMethod()`、`getRequestURI()` 有啥用？

- `HttpServletRequest`：请求对象，能拿请求方法、路径、请求头、参数、body。
- `getMethod()`：GET 还是 POST。
- `getRequestURI()`：路径，如 `/hello`，不含 `?` 后面的参数。
- 要强转是因为 Filter 接口给的是通用款 `ServletRequest`，HTTP 专用方法只在 `HttpServletRequest` 上。

### `@Component`、`@Override`、`implements` 是啥？

- `implements Filter`：声明实现 Filter 接口，必须交出 `doFilter` 方法。接口就是一份合同。
- `@Component`：告诉 Spring 启动时创建这个类并注册成过滤器。
- `@Override`：给编译器看的，声明「这是重写接口的方法」，名字写错立刻报错。可省略，不建议省。

### `static final` 里的 `final` 干嘛用？

`final` 锁的是"这个变量指向哪个对象"，不是锁内容。写了 `final` 之后不能再 `TOKENS = new HashMap<>()`（编译报错），但 `put`、`remove` 照样能用。

加它的原因：这是全站唯一的一本登记本，钉死在类上，防止哪次手滑把它替换成一张空表，所有登录状态瞬间清空。

### `chain` 是干啥的？

`chain` 是过滤器的"下一关钥匙"，由 Tomcat 传进来，代表"剩下的过滤器和最终 Controller"。

`chain.doFilter(request, response)` 的意思是：我这一关查完了，放行。不调它，请求就停在当前过滤器，页面转圈。

### `getHeader("Authorization")` 是啥？

从请求头里按名字取一个值。请求头就是跟着请求走的一堆"名: 值"，比如 `Authorization: 3ff1...`。

`Authorization` 是 HTTP 标准里专门放凭证的头，curl、浏览器、Postman、各种框架都认这个名字。名字可以自己改，但改了就得自己发、自己收，别人不认。

### `getWriter().write(...)` 是啥？

`resp.getWriter()` 拿到响应的"笔"（往响应正文写字符的流），`write(...)` 把字符串写进去。它和 `setStatus(403)` 配合：一个定状态码，一个定正文。

坑：调了 `getWriter()` 就不能再用 `getOutputStream()`，两者只能用一个。

### 403 中文变成问号是怎么回事？

`getWriter()` 默认按 `ISO-8859-1` 输出，中文塞进去就变成 `?`。要显式告诉它用 UTF-8：

```java
resp.setContentType("text/plain;charset=UTF-8");
```

写在 `getWriter().write(...)` 之前。

## 第 5 步：过滤器校验（已过）

- 登录时用 `TokenStore.save(token, username)` 登记，过滤器用 `TokenStore.getUsername(token)` 查。
- 过滤器先放行 `/login`（否则拿不到第一张纸条），再取 `Authorization` 请求头，查不到就 403。
- 每个拦截分支都要 `return`，只有最后才 `chain.doFilter` 放行。
- 坑：`resp.getWriter()` 默认 ISO-8859-1，中文变问号，要 `resp.setContentType("text/plain;charset=UTF-8")`。

## 第 6 步：纸条 5 分钟过期（已过）

- 登记本的值从 `String` 改成 `Entry`（username + issueAt 毫秒时间戳）。
- `System.currentTimeMillis()` 取当前时间戳，两个一减就是毫秒差。
- `TTL` 常量表示存活时长，`isExpired` 用「现在 - 签发时间 > TTL」判断。
- 查不到也当过期，过滤器少判一次空。
- 测试技巧：把 TTL 临时改成 `5 * 1000`，6 秒后访问就该 403；测完改回 `5 * 60 * 1000`。
- 别用「重启后旧纸条 403」证明过期生效——那是内存被清空了。

## 疑问记录（补充）

### `Entry` 为什么写在 `TokenStore` 里面？

Java 允许类嵌套类。`Entry` 只服务于登记本，放里面一眼看出归属，全名是 `TokenStore.Entry`。单独建 `Entry.java` 也能跑，不是强制。

### `Entry e = TOKENS.get(token);` 为什么拿到的是 Entry？

因为声明的是 `Map<String, Entry>`，值的类型就是 `Entry`。`get` 返回值的类型，编译器会检查；写成 `String e = ...` 直接编译报错。

### GET 和 POST 的区别

GET 取数据，参数在网址 `?` 后；POST 提交数据，参数在正文里；GET 会进历史/日志，POST 不会。当前 `/login` 用 GET 只是为了浏览器方便测，正式应该改 POST（密码不该出现在网址里）。

### 堆栈怎么读

第一行是异常类型 + 原因；`at` 行从上往下是调用链；跳过 `org.springframework`、`jakarta`、`java.` 开头的，找第一个 `com.example.jwt_lab`，末尾括号就是文件名和行号。

## 第 7 步：换成真 JWT（已过）

- 7a：登录用 `JwtService.create()` 生成 JWT（HS256，密钥 32 字节以上），返回三段字符串；payload 里是 sub / iat / exp。
- 7b：过滤器改成 `jwtService.verify(token)` 验签，不再查登记本；`TokenStore` 停用但保留供对照。
- `verify` 做两件事：用密钥重算签名比对（防篡改）、取出 sub；签名错/过期/格式错都返回 null。
- 验签靠密钥，不靠存储：服务重启后旧 JWT 依然有效——这是与阶段 A 最大的区别。
- 坑：从终端复制令牌时会把行尾 `%` 带上，导致 403。用 `T=$(curl ...)` 存变量，别手抄。

## 疑问记录（补充）

### 解析器是啥，为什么需要？

JWT 是文本，判断可信要做一串固定动作（切段、解码、重算签名、比 exp）。jjwt 把这些封装成"解析器"，`Jwts.parser().build()` 出来才能用。类比验钞机。

### `verify` 干了什么？

验签（重算签名并比对）+ 取 sub；出错返回 null。它回答"可信吗、是谁"。

## 约定

- **每步之后留提问环节**：用户会先问问题，答完、他说没有疑问，才进下一步。不要跳过。
- **输出格式**：一步一步给，每一步先讲这一步要干什么、为什么，代码紧跟在讲解下面。不用折叠标签（界面会直接展开，达不到收起效果）。

- **分部解释 + 分部代码**：每个决策点先讲为什么，紧接着写「所以我们怎么写」，再给这一小段代码。每步末尾再给该步完整文件代码，方便对照拼接。

- **每段代码前加一句引导**：如"接下来我们创建 save 方法""接下来写一个 if 判断"，让人知道马上要写什么。
- **用陈述句讲**：默认直接说"这里要干什么、接下来干什么"，不拿设问句当小标题。只有真正值得单独强调的点，才用一个设问句加强。
